# 版本与验证

版本以 `构建信息.json` 和本版 `distribution.json` 为准；源码根 `package.json` 的版本须与 `desktopVersion` 一致。不能只根据压缩包名称、`.app` 名称或界面文字判断新旧。

本版有三个不同的验证层次：

1. **产物文件一致**：完整解压后在分享包根目录运行 `shasum -a 256 -c SHA256SUMS`。它核对包中包括 APK、Mac 应用、文档的逐文件摘要；来源可信度仍要自行确认。Mac 还应执行 `codesign --verify --deep --strict`；ad-hoc 签名不是 Apple 公证。
2. **运行源码封版一致**：内置 `verify-distribution.mjs` 检查 `runtime-manifest.json` 对应的全部 `src/`、`web/`、`config/`、`distribution.json`、`package.json`、`package-lock.json`；新增、删除、改字节或符号链接都不能冒充原封版。它同时核 distribution/BUILD_IDENTITY，分享版还核桌面 runtime.json 的期望身份。
3. **实际进程一致**：加 `--running` 后，在本版 loopback 端口先取得本机会话 Cookie，再读取受保护 health，逐项核 edition、Mac version、sourceDigest、Android applicationId/version/code。检查的是进程启动时缓存的源码身份，替换磁盘文件不能让旧进程冒充新代码。不会启动、杀死或重配服务。

## 命令

分享包安装后的 `.app` 自带 Node，先将路径填成实际本版应用：

```sh
boujoy_app='/Applications/替换为本版应用名.app'
boujoy_resources="$boujoy_app/Contents/Resources/app"
"$boujoy_resources/runtime/node" "$boujoy_resources/backend/scripts/verify-distribution.mjs" --json
"$boujoy_resources/runtime/node" "$boujoy_resources/backend/scripts/verify-distribution.mjs" --running --json
```

完整源码在根目录运行：

```sh
node scripts/verify-distribution.mjs --json
node scripts/verify-distribution.mjs --running --json
```

可用 `--root /绝对/源码或backend目录` 明确要检查的根目录；开发服务使用了自定义端口时加 `--running --origin http://127.0.0.1:实际端口`。只接受本机 127.0.0.1 HTTP，不跟随重定向。

| 退出码 | 结果 |
|---|---|
| 0 | `sealed` 表示离线封版一致；`running_verified` 才包含实际进程验证 |
| 2 | `unsealed`，缺少清单，明确未封版，不是发布通过 |
| 1 | 校验、身份、会话或服务失败；未更改或终止任何服务 |

脚本只输出公开构建身份、结果和受控错误文字；不打印 Cookie、CSRF、密钥、个人路径或完整 health。不要用 `npm run doctor` 的原始输出替代它公开贴出，因为 doctor 的排查信息可能包含本机路径。

## Android 与测试边界

Android 打包额外检查实际 APK manifest 的 applicationId/version/code、签名与 SHA256；相邻构建收据记录 Android 输入文件映射。打包器重新遍历 `android/app/src` 和 Gradle/distribution 输入，检测新增、删除、字节变化，不能只用 mtime 或文件名宣称“新 APK”。这层检查与运行后端源码摘要不同。

运行源码清单不覆盖 Node 依赖、桌面壳、Android、文档或用户状态，所以仍需要包级 SHA、签名与对应测试。摘要不是对所有功能的保证，验证器不会自动执行手机任务或部署服务器。

实际发布验收记录应单独列出：Node 测试、Android 单元/构建、离线摘要、Mac 首启/真实进程、手机新包名安装和重绑、主屏读写与停止、Xiaomi 后台/背屏、语音、relay 公网证书与移动网络。某项未执行就明确写“未实测”。

两个公开版的新 applicationId 需要分别进行真机安装与重绑验收，公网部署也需独立验证。通用版面向 Android 13+，不代表所有品牌/机型都经过验收。两版可并存但没有跨版全局手机执行租约，同手机一次只由一版操作。
