# 排错

先查包内 `构建信息.json` 与应用内 `distribution.json`，确认是 Phone Use 还是 Xiaomi。先保存可恢复的本人数据，不通过卸载、清空钥匙串或覆盖数据来试错。向他人提供日志前去掉密钥、绑定码、Cookie、路由、路径、手机标识、聊天和截图；运行校验器只输出允许公开的构建身份。

## 封版或实际进程验证失败

| 结果 | 含义 | 处理 |
|---|---|---|
| `unsealed` / 退出 2 | 缺少 runtime-manifest.json | 开发源码可以继续开发；分享包需向提供者获取已封版产物，不能假称通过 |
| `source_mismatch` | 文件新增、删除、修改或符号链接 | 重新获取完整可信包；开发者审查变更并重新发布，不在接收者电脑上重写清单 |
| `identity_mismatch` | edition、版本、hash 或 Android 身份不同 | 保留现有进程；确认来源和任务状态后正常停止旧版本，启动目标版再验证 |
| `service_unavailable` | 服务未启动、超时或重定向 | 先打开目标应用；核实际端口，不改成远程地址，不反复启动多个后端 |
| `session_failed` / `health_failed` | 不是本版认证服务或认证请求失败 | 不能以首页可访问代替成功；核是否旧程序占用本版端口，保留并核查其启动方式 |
| `distribution_invalid` / `runtime_invalid` | 配置与源码/桌面身份不一致 | 重新构建正确 edition，不能只改 app 名、端口或 JSON 字段凑数 |

源码开发者换了端口，可运行 `node scripts/verify-distribution.mjs --running --origin http://127.0.0.1:实际端口`；仅支持明确的本机地址。验证脚本不会终止任何进程。

Mac 窗口关闭不等于服务退出。确认旧服务来自源码常驻安装时，在**对应版本的源码**正常执行 `npm run service:uninstall`；前台开发进程在原终端正常结束。不要用广域 kill 命令清场。停止后重新启动目标版并再核 hash，不能只看磁盘文件已替换。

## Mac 无法打开或功能缺失

- 先做包 SHA-256 与 `codesign --verify --deep --strict`。本包是 arm64，未提供 Intel 二进制，也未声称 Apple 公证。由本人按系统界面处理可信包的首次打开；不要关闭系统安全机制。
- 分享版已带后端、Node、Python 和 Harness；源码版需要 `npm ci`、`npm run setup`。把 `npm run app` 产物搬到别的机器会缺源码，这时应取完整分享包。
- 模型连接失败在“设置 → 连接 → DeepSeek”更新自己的凭证、核账户状态和网络。勿贴 Key。请求数达到限制不等于网络坏，也不等于金额账单已清零。
- 浏览器任务需要 Playwright Chromium 或 Google Chrome；源码可用 `npx playwright install chromium`。不要复制个人浏览器档案来“解决登录”。
- 语音输入是可选能力，当前优先使用 DeepSeek，音频/朗读文本可能外发；本机回退需准备模型、ffmpeg 与环境，并由本人授权麦克风。无录音/转写时按源码 `docs/local-voice.md` 排查，不以文字聊天成功推断语音可用，也不声称全程本地。

## Android 安装、连接与输入

- `INSTALL_FAILED_UPDATE_INCOMPATIBLE` 或签名冲突：核 applicationId 与签名来源。**不自动卸载、不清数据**。同 applicationId 更新需要原签名；恢复正确签名或由本人制定备份迁移方案。
- 只有 Phone Use 已安装：可以先配对 Mac 做局域网主屏任务。Boujoy Android 是手机聊天与补充能力端，手机聊天还需要 relay，不会凭 APK 自动上线。
- HTTPS 地址连不上：读取手机当前显示的地址；检查同一局域网、访客网络隔离、VPN/防火墙、Phone Use 是否正在运行。不要关闭 TLS 校验、开放公网 ADB 或转发手机端口。
- 配对等待：两端安全码本人核对一致后确认。取消/失败不假定已切换设备，不从旧记录找分享者手机复用。
- 点击/输入失败：保持主屏亮着解锁，核无障碍状态及实际所选手机；需要 Boujoy 无线输入时按手机设置亲手授权。不同品牌的后台限制分别检查，不把系统限制改写成“都支持”。
- 两版都连了同一手机：结束或暂停一边任务，再继续另一边。应用身份隔离不等于跨版操作互斥。

## Xiaomi 后台/背屏未就绪

按状态逐项看 Shizuku 是否运行并授权、“Boujoy 后台执行”无障碍是否开启、后台显示是否成功创建。非 Xiaomi edition 没有后台开关是预期行为。

“背屏进度”开启只是偏好，不保证实际背屏创建成功；锁屏权限与电源租约也有独立检测。特定型号/系统构建白名单之外可能明确拒绝，系统更新后需重新验证。不要改机型字段、绕过白名单或宣称全部小米支持。后台失败时任务保持暂停，由本人决定切回主屏并重新继续。

## relay 与手机聊天离线

1. 先核 Mac 在线、手机联网、绑定没有过期/撤销，relay 地址是本人的地址；Mac 合盖或休眠时不能保证在线。
2. 检查部署文档中的 HTTPS 证书、路由哈希表和容器状态。公网 `/healthz` 成功只证明 relay 响应，不代表该手机获准连接。
3. 分别验证 data/control 连接、真实消息与停止、Wi-Fi/移动网络重连。消息接收结果未确认时查询原消息，不重复提交同一操作。
4. 路由表更新按部署脚本重建对应挂载；不要上传完整 DATA、state.json、私钥或配对文件。不会部署时先保留局域网主屏路线。

源码版继承的历史单元/本机传输测试不是本次公网验收。新公开 appId 未有真机重绑记录时，必须明确标为未实测。
