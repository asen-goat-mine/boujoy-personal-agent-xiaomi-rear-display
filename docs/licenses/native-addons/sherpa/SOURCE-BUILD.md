# Source delivery and reconstruction materials

The `includedArchives` list in sources.json is the complete inventory of files delivered here. Each **included source archive** is an unchanged full upstream source distribution. It includes Sherpa-ONNX at the exact npm registry gitHead, eSpeak NG, Piper phonemize, kaldi-native-fbank, KISS FFT, kaldi-decoder, kaldifst, OpenFST, Eigen, simple-sentencepiece, JSON, hclust and node-addon-api 8.3.0. Archive SHA256 values are recorded; the CMake-selected archives match the hashes in the fixed upstream build recipes. Both installed npm Sherpa packages were checked against npm integrity, with all 26 installed package members matching the original published tarballs.

The separate ONNX Runtime shared library is an MIT-licensed build dependency. Its exact 1.28.2 prebuilt archive (including headers) is included and its dylib matches the distributed dylib byte for byte. Its full original MIT/third-party notices are retained. The 1.28.2 complete source download URL and verified source-archive SHA256 are recorded separately as **source URL only**; this permissive library's 278 MB source archive is not duplicated here. It is not represented as an included source archive.

The entire Sherpa source archive contains the original CMake files, Node wrapper sources, Node package manifest, `.github/workflows/npm-addon-macos.yaml`, `.github/scripts/node-addon/run.sh`, and platform recipes. Selected entry points are also directly readable under source-evidence. No local native-source patches were applied. The eSpeak/Piper forks and all recipe-specific changes are already in the included fixed-commit archives.

For a local reconstruction, extract the Sherpa archive, read the original macOS workflow, and provide a C/C++ compiler, CMake, make and Node/npm. The workflow uses Node 24, configures `BUILD_SHARED_LIBS=ON`, disables WebSocket, PortAudio and standalone binaries, builds/installs the libraries, then sets `SHERPA_ONNX_INSTALL_DIR` to that installation and builds `scripts/node-addon-api` with cmake-js. The source archives' original filenames are in their recorded URLs; put copies under those names in the locations recognized by the original recipes, or use CMake's corresponding `FETCHCONTENT_SOURCE_DIR_<NAME>` overrides after extracting them. The included ONNX prebuilt supplies its original include/lib directories. Do not run any release/publish step merely to rebuild locally.

The upstream wrapper requests node-addon-api `^8.3.0` and cmake-js `^7.3.0` without a committed npm lockfile. A complete compatible node-addon-api 8.3.0 source is supplied to make the header source available; this is not a claim that 8.3.0 was the original build's resolved patch version. Generic build tools and their optional packages may still need installation. This is offline **source delivery**, not a preinstalled offline toolchain. The native libraries were not rebuilt during this audit and byte-for-byte reproducibility is not claimed.

The GPLv3 eSpeak COPYING text and original copyright notices accompany these sources. Recipients may obtain, modify and build these included sources without contacting this distributor or depending on continued operation of the original download URLs. Keep the source archives, recipe/patch materials and notices with onward copies of the related binaries. This source-provision verification is a technical record; it does not purport to decide every possible legal boundary of an entire combined application.

## Optional upstream example links

The unchanged upstream source tar contains two absolute symbolic links in `scripts/go/_internal/vad-spoken-language-identification/` (`main.go` and `run.sh`) pointing to an upstream developer checkout. They are unused by the selected C++/Node build and remain sealed in the source archive; they are not filesystem links in the delivered application. When extracting for this build, exclude those two optional Go-example members, or replace them in your working copy with the corresponding regular files in `go-api-examples/`. Do not follow these upstream checkout links. The original source archive is unchanged; its source identity is recorded in sources.json.
